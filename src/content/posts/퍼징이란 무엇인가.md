## 1. 퍼징이란?

**퍼징(Fuzzing)** 은 소프트웨어에 무작위 또는 반-무작위(semi-random) 입력값을 대량으로 공급하여 예상치 못한 동작(크래시, 행, 메모리 오류 등)을 유발시키는 **자동화된 취약점 탐지 기법**이다.

1988년 바턴 밀러(Barton Miller) 교수가 Unix 유틸리티 프로그램에 무작위 문자를 입력했을 때 25~33%가 크래시 됨을 발견한 것이 시초이다. 오늘날에는 구글, 마이크로소프트, 애플 등 빅테크 기업에서 프로덕션 배포 전 필수 보안 검증 단계로 사용하고 있다.

### 퍼징이 찾는 버그 유형

| 버그 유형 | 설명 |
|-----------|------|
| Buffer Overflow | 버퍼 경계를 넘어 메모리 쓰기 |
| Use-After-Free | 해제된 메모리 재참조 |
| Heap Corruption | 힙 메모리 손상 |
| Integer Overflow | 정수 범위 초과 |
| Null Pointer Dereference | 널 포인터 역참조 |
| Format String Bug | 형식 문자열 취약점 |
| Logic Error | 예외 상황에서의 논리 오류 |

## 2. 퍼징의 종류

퍼징은 크게 **대상 프로그램 내부를 얼마나 알고 있는가**에 따라 세 가지로 분류된다.

### 2-1. 블랙박스 퍼징 (Black-box Fuzzing)

프로그램 내부 구조(소스코드, 바이너리)에 대한 정보 없이 **입출력만**으로 퍼징하는 방식이다.

- **장점:** 소스코드 없이도 적용 가능, 설정이 간단
- **단점:** 코드 커버리지가 낮음, 깊은 경로 탐색이 어려움
- **예시:** 단순 랜덤 데이터 전송, 네트워크 프로토콜 퍼징

### 2-2. 화이트박스 퍼징 (White-box Fuzzing)

소스코드나 바이너리를 완전히 분석하여 **심볼릭 실행(Symbolic Execution)** 기반으로 입력값을 생성하는 방식이다.

- **장점:** 이론적으로 모든 코드 경로 탐색 가능, 높은 정밀도
- **단점:** 느리고 리소스 소모가 큼, 복잡한 프로그램에서 경로 폭발(path explosion) 문제 발생
- **예시:** SAGE(Microsoft), KLEE

### 2-3. 그레이박스 퍼징 (Grey-box Fuzzing) ← 현재 주류

바이너리 계측(instrumentation)을 통해 **코드 커버리지 피드백**을 수집하고, 새로운 경로를 탐색하는 입력값을 우선 변이(mutation)시키는 방식이다.

- **장점:** 블랙박스보다 효율적, 화이트박스보다 빠름, 실용적
- **단점:** 계측 오버헤드 존재, 내부 상태를 완전히 파악하지 못함
- **예시:** AFL, AFL++, libFuzzer, Jackalope

```
[그레이박스 퍼징 동작 흐름]

초기 시드(seed) 입력
       ↓
  타겟 프로그램 실행
       ↓
  커버리지 수집 (새 경로?)
       ↓ YES
  시드 큐에 추가
       ↓
  변이(mutation) 적용
       ↓
       └──────────────→ 반복
```

### 2-4. 뮤테이션 기반 vs 생성 기반

| 구분 | 뮤테이션 기반 (Mutation-based) | 생성 기반 (Generation-based) |
|------|-------------------------------|------------------------------|
| 방법 | 기존 입력값을 변형 | 문법/스펙에 따라 새 입력 생성 |
| 장점 | 유효한 입력에서 시작, 구현 간단 | 구조적으로 올바른 입력 생성 가능 |
| 단점 | 초기 시드 품질에 의존 | 문법 정의 작성이 필요 |
| 예시 | AFL++, libFuzzer | Peach, Boofuzz, Domato |

## 3. 대표적인 퍼저들

### 3-1. AFL++ (American Fuzzy Lop plus plus)

> 링크: [https://github.com/AFLplusplus/AFLplusplus](https://github.com/AFLplusplus/AFLplusplus)

AFL은 Google의 Michal Zalewski가 개발한 그레이박스 커버리지 기반 퍼저로, AFL++은 그 커뮤니티 개선 버전이다. 현재 가장 널리 쓰이는 퍼저 중 하나이다.

#### 핵심 특징

- **컴파일 타임 계측:** `afl-gcc`, `afl-clang-lto` 등을 이용해 소스코드 컴파일 시 커버리지 추적 코드를 삽입
- **QEMU 모드:** 소스코드 없이 바이너리만으로도 퍼징 가능 (성능 하락 있음)
- **변이 전략:** 비트 플립, 산술 연산, 블록 교체, 딕셔너리 기반 변이 등 다양한 방식 지원
- **병렬 퍼징:** 마스터-슬레이브 구조로 멀티코어 활용
- **커버리지 피드백:** 엣지 커버리지(edge coverage) 기반으로 새로운 경로 탐색

#### AFL++ 개선 사항 (AFL 대비)

| 기능 | AFL | AFL++ |
|------|-----|-------|
| 변이 스케줄링 | 기본 | MOpt, Custom Mutator API 지원 |
| 계측 | afl-gcc | LTO 계측, LLVM 최적화 |
| 커버리지 | 엣지 | Context-sensitive edge coverage |
| QEMU | 기본 지원 | 개선된 QEMU/Unicorn 모드 |
| CmpLog | 없음 | 비교 연산 로깅으로 매직 값 탐색 |

#### 기본 사용 예시

```bash
# 소스코드 컴파일
CC=afl-clang-fast ./configure
make

# 퍼징 시작
afl-fuzz -i seeds/ -o output/ -- ./target_binary @@
# @@는 퍼저가 생성한 입력 파일 경로로 대체됨
```

### 3-2. Jackalope

> 링크: [https://github.com/googleprojectzero/Jackalope](https://github.com/googleprojectzero/Jackalope)

Google Project Zero에서 개발한 **바이너리 전용** 커버리지 기반 퍼저이다. 소스코드 없이 Windows/macOS 환경에서 동작하도록 설계되었으며, Tinyinst를 동적 계측 라이브러리로 사용한다.

#### 핵심 특징

- **동적 바이너리 계측:** Tinyinst를 사용하여 실행 중 바이너리를 계측 (소스코드 불필요)
- **크로스 플랫폼:** Windows와 macOS 모두 지원
- **확장성:** 커스텀 mutator, sample delivery 메서드를 쉽게 추가 가능
- **네트워크/IPC 지원:** 파일 입력 외에 네트워크 소켓, 공유 메모리 등 다양한 입력 방식 지원
- **바이너리 타겟:** 클로즈드 소스 애플리케이션 퍼징에 최적화

#### AFL++과의 비교

| 항목 | AFL++ | Jackalope |
|------|-------|-----------|
| 주요 플랫폼 | Linux | Windows, macOS |
| 계측 방식 | 컴파일 타임 (+ QEMU) | 동적 계측 (Tinyinst) |
| 소스코드 필요 | 권장 (QEMU로 우회 가능) | 불필요 |
| 성숙도 | 매우 높음 | 중간 |
| 생태계 | 매우 풍부 | 상대적으로 작음 |

### 3-3. libFuzzer

Google이 개발하고 LLVM에 포함된 **인프로세스(in-process)** 커버리지 기반 퍼저이다.

#### 핵심 특징

- **인프로세스:** 타겟 함수를 별도 프로세스 없이 동일 프로세스 내에서 반복 호출 → 매우 빠름
- **LLVMSanitizers 통합:** ASan, MSan, UBSan과 함께 사용하면 버그 탐지율 극대화
- **간단한 통합:** `LLVMFuzzerTestOneInput` 함수 하나만 구현하면 됨
- **구조적 퍼징:** `libprotobuf-mutator`와 결합하여 복잡한 구조체 입력 생성 가능

```c
// libFuzzer 타겟 함수 예시
#include <stdint.h>
#include <stddef.h>

int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) {
    // 여기에 퍼징할 코드를 넣는다
    if (size > 0 && data[0] == 'F') {
        if (size > 1 && data[1] == 'U') {
            // 취약한 코드 경로
        }
    }
    return 0;
}
```

### 3-4. Google Fuzzing (OSS-Fuzz)

> 링크: [https://github.com/google/fuzzing](https://github.com/google/fuzzing)

Google이 운영하는 오픈소스 프로젝트 자동 퍼징 서비스 및 퍼징 관련 가이드, 도구 모음이다.

#### OSS-Fuzz 특징

- **지속적 퍼징:** 오픈소스 프로젝트를 Google 인프라에서 24/7 자동 퍼징
- **스케일:** 수천 개의 코어로 병렬 퍼징 수행
- **멀티 엔진:** AFL++, libFuzzer, Honggfuzz 등 다양한 퍼저 앙상블 사용
- **자동 보고:** 크래시 발견 시 자동으로 개발자에게 보고
- **성과:** 발견 취약점 1만 건 이상 (OpenSSL, curl, SQLite 등)

## 4. 퍼저 비교

### 종합 비교표

| 항목 | AFL++ | Jackalope | libFuzzer | OSS-Fuzz |
|------|-------|-----------|-----------|----------|
| 퍼징 유형 | 그레이박스 | 그레이박스 | 그레이박스 | 앙상블 |
| 주요 플랫폼 | Linux | Windows/macOS | 크로스플랫폼 | Linux (클라우드) |
| 소스코드 | 권장 | 불필요 | 필요 | 필요 |
| 계측 방식 | 컴파일/QEMU | 동적(Tinyinst) | 컴파일(LLVM) | 다양 |
| 속도 | 빠름 | 보통 | 매우 빠름 | - |
| 진입 장벽 | 낮음 | 중간 | 낮음 | 높음 |
| 바이너리 전용 | QEMU 모드 | 기본 지원 | 불가 | - |
| 커뮤니티 | 매우 활발 | 보통 | 활발 | Google 관리 |

### 언제 어떤 퍼저를 쓸까?

| 상황 | 추천 퍼저 |
|------|-----------|
| Linux 오픈소스, 소스코드 있음 | **AFL++** 또는 **libFuzzer** |
| Windows 클로즈드 바이너리 | **Jackalope** |
| 빠른 인프로세스 퍼징 | **libFuzzer** |
| 프로토콜/파일 포맷 퍼징 | **AFL++ + 커스텀 mutator** |
| 대규모 지속적 퍼징 | **OSS-Fuzz** |

## 5. 정리

퍼징은 현대 보안 연구와 버그 바운티에서 핵심 기법 중 하나로, 자동화된 방식으로 수많은 취약점을 발견할 수 있다.

**핵심 요약:**
- 퍼징 = 무작위/변이 입력으로 프로그램의 예외 동작을 유발해 취약점 찾기
- **그레이박스 퍼징**이 현재 주류: 커버리지 피드백으로 효율적 탐색
- **AFL++**: Linux 환경의 범용 퍼저, 생태계 가장 풍부
- **Jackalope**: Windows/macOS 바이너리 퍼징에 특화
- **libFuzzer**: 빠른 인프로세스 퍼징, LLVM과 통합
- **OSS-Fuzz**: Google 클라우드에서 오픈소스 대상 대규모 지속 퍼징

버그 바운티 관점에서는 **AFL++** 또는 **libFuzzer**로 시작해 타겟 환경에 따라 도구를 선택하는 것을 권장한다.
